            <h1>How to Help-Enable Visual Force Pages</h1>
            <br/>
            <h2>Overview</h2>
            <p>Improved Help supports the development of helped Visual Force pages that include Apex form tags in various scenarios:</p>
            <ul>
                <li><b>Apex Detail</b>: to embed a virtual standard page layout into the Visual Force page;</li>
                <li><b>Apex Page Blocks and form tags</b>: to embed partial forms in classic tabular layout;</li>
                <li><b>Apex 'stand-alone' form tags</b>: to embed data management elements in more free-form pages.</li>                
            </ul>
            
            <b>NOTE: In all cases, the Help Topic Author remains in control of Help Callout template choice and rendered height - 
            Visual Force page working outside of classic salesforce tabular form layouts need to consider callout container height and overflow accordingly.</b>

            <hr/>
            
<!-- ========== Apex Detail tag ========== -->
                         
            <br/>
            <h2>Help-Enabling classic salesforce user interface 'tabular' elements</h2>
            <br/>
            <h3>The Apex Detail tag</h3>
            <br/>
            In this simplest scenario, the Visual Force page takes on a classic, standard page user interface and layout. 
            Improved Help standard hooking code recognises the way Apex form tags are rendered and manages help callouts automatically.
            <br/>
            <br/>
            Development tasks:
            <ul>
                <li><b>Page-level markup</b>: Include for IHHookpage;</li>
                <li><b>Element-level markup</b>: None required;</li>
            </ul>
            Help Authoring tasks:
            <ul>
                <li><b>Helped Page Layout record</b>: required with Identifier = Visual Force page name;</li>
                <li><b>Helped Element records</b>: Required and can re-use any Help Topics associated with Helped Elements in the standard page;</li>
                <li><b>Help-Enable Mode</b>: Available to Help Authors if Visual Force page has showHeader = true AND sidebar = true.</li>
            </ul>

            <div style="width: 90%; margin: auto; border: 1px solid silver; border-radius: 4px;">

            </div>

            <h2>Help-enabling general HTML and 'stand-alone' Apex elements</h2>
            <p>Improved Help supports developers who want to break free from the constraints of the classic salesforce tabular form layout.</p>

<!-- Command Buttons and Links -->

            <h3>Apex Command Buttons</h3>
            <p>Improved Help hooking code recognises Apex Command buttons and automatically manages Help Callout positioning - 
            by inserting a table row. So, to use a Command Button, place it in a suitably structured table layout to allow automated callout positioning.
            If a table layout is not desired, consider using an Apex Action linked to a general HTML tag - see below.</p> 

<!-- Command Buttons Element Starts -->
                    
            <div style="width: 40%; margin-left: 5%; background: #ffffff; border: 1px solid silver; border-radius: 4px; padding: 10px;">
                <table width="100%" border="0">
                    <tr>
                        <td>
                            <apex:commandButton value="Custom View Button" id="CommandButtonStandAlone"/>
                        </td>
                    </tr>
                </table>
            </div>

<!-- Command Buttons Element Ends -->
                    
            <p>Development tasks:</p>
            <ul>
                <li><b>Tag type</b>: Create a table structure - with nested table, 'tr'and 'td' containers - around the target tag to be helped;
                The table width will set the width of the Help Callout when opened.</li> 
                <li><b>Markup - unique ID</b>: Developer decides;</li>
                <li><b>Styling</b>: The enclosing table width will constrain Help Callout width; 
                Improved Help hooking code assigns IHHelpedVFElement class when Helped Element record exists.</li>
            </ul>
            Help Authoring tasks:
            <ul>
                <li><b>Helped Page Layout record</b>: required with Identifier = Visual Force page name;</li>
                <li><b>Helped Element records</b>: Required, with Helped Element Identifier referencing tag unique ID.</li>
            </ul>

<!-- ========== Callout Management ========== -->
            
            <h3>Individual Apex tags: Callout Position and Size</h3>
            <p>In classic salesforce pages, Help callouts are constrained by the tabular form layout.
            In more free-form Visual Force page layouts, the page developer can control help callout:</p>
            <ul>
                <li>Opening position: relative to the mouse position, relative to the edge of the Helped Element or in a specified div;</li>
                <li>Direction: extending left or right of the mouse/element;</li>
                <li>Width: as a percentage of the screen available in the selected direction from the mouse/element.</li>                
            </ul>
            <b>NOTE: The Help Author is always in control of Callout height, so ensure that height and overflow parameters are set appropriately for the page design.</b>
            <br/>

<!-- Apex tags without on-click events -->
            
            <h3>Apex tags with no on-click event</h3>
            <p>*Tags with no native click event - in tag markup or in any listener function - can be help-enabled directly.
            The *Apex OutputText* example in the above table shows the behaviour of this approach. As this is not how 
            Improved Help supports standard salesforce pages, a separate 'click-helper' element - as used for Apex tags with their own 
            on-click event - could help with creating a uniform, cohesive user experience.</p>  
            Development tasks:
            <ul>
                <li><b>Page-level markup</b>: Include IHHook;</li> 
                <li><b>Element-level markup</b>: Add enclosing div or span with a unique ID and the addition of the class 'Helpable';</li>
            </ul>  
            Help Authoring tasks:
            <ul>
                <li><b>Helped Page Layout record</b>: required with Identifier = Visual Force page name;</li>
                <li><b>Helped Element records</b>: Required, with Helped Element Identifier referencing tag unique ID.</li>
            </ul>

<!-- Apex tags with on-click events -->

            <h3>Apex tags with existing on-click events</h3>
            <p>Tags with a click event need a separate 'Click Helper' element to provide the 'Help Available' visual cue and 'Show Help' 
                click event. If users interact with Improved Help in standard pages, you may elect to replicate the click-helpers seen there: divs or spans 
                containing labels or icons as background images.</p>
            Development tasks:
            <ul>
                <li><b>Page-level markup</b>: Include IHHook;</li>
                <li><b>Element-level markup</b>: Add an inline div or span before the target Apex tag, with a unique ID and appropriate 
                'Helpable' classes and parameter variations, as descibed above, to set the desired Help Callout size and direction.</li>
            </ul>  
            Help Authoring tasks:
            <ul>
                <li><b>Helped Page Layout record</b>: required with Identifier = Visual Force page name;</li>
                <li><b>Helped Element records</b>: Required, with Helped Element Identifier referencing tag unique ID.</li>
